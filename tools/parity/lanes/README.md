# Lane modules

Lanes that live outside `parity_harness.py` register themselves with
`register_lane` / `register_controls` and are loaded with `--lane-module` on
both `calibrate` and `run`. A loaded module enters the harness fingerprint, so a
calibration only vouches for the exact lane code it ran with.

## `browser_lanes.py`: oracle, reimport, rejection

| Lane | Compares | Fails closed on |
|---|---|---|
| `oracle` | each side's native render against one Chromium screenshot taken by the browser itself (`oracle.png`, no importer code involved), cropped to the case's `params.oracle_clip_*` | a capture that differs between the two processes or has no browser version (`blocked`); a DesignIR node that paints browser pixels; a render identical to the capture; a capture made by a different browser; mismatch above the case ceiling (≤ 10%, justified); a candidate further from Chromium than the reference |
| `reimport` | the unchanged source imported again (`second/`) and after `args.revision` (`revision/`) | output not bound to the bytes it came from (stale); an unchanged reimport that differs; an undetected edit; an edit that keeps no identity; sides detecting different changes |
| `rejection` | `outcome.json` written by `outcome_recorder.py` for an `expect`ed `reject` or `warn` | the wrong outcome or code; a crash or timeout (never a rejection); sides that disagree |

The oracle lane is a browser-fidelity row, never native parity: the core
`raster`/`geometry` lanes carry that. Implementation side:
`implementations/pulp-browser-native.json`.

```sh
python3 tools/parity/parity_harness.py calibrate \
  --lane-module tools/parity/lanes/browser_lanes.py \
  --corpus tools/parity/corpus/browser-calibration.json \
  --source-root <checkout> --implementation tools/parity/implementations/pulp-browser-native.json \
  --tool importer=<pulp-import-design> --tool observer=<pulp-design-ir-observe> \
  --root checkout=<checkout> --root build=<build dir> --out <dir>
```

`corpus/rejection-calibration.json` calibrates the rejection lane the same way.
`corpus/rejection-contract-gaps.json` lists malformed inputs the calibrated
implementation does not yet handle; run it with `run --mode calibration` and
expect it to stay non-accepting until each gap is fixed. Its inputs are
generated by `corpus/fixtures/malformed/generate.py` (`--check` verifies the
committed bytes). Unit tests: `python3 tools/parity/test_browser_lanes.py`.
